## III. SYSTEM MODELING

We consider a Space-Terrestrial Integrated Network (STIN) consisting of a Low Earth Orbit (LEO) satellite constellation, Ground User Terminals (UTs), and Ground Stations (GS) connected to cloud servers. The system is modeled as a discrete-time system with time slots $t = 1, 2, \dots, T$.

### A. Network Architecture

The LEO constellation consists of a set of satellites $\mathcal{S} = \{s_1, s_2, \dots, s_N\}$. The satellites are organized in a Walker Delta constellation (e.g., Iridium-like configuration) with $N=66$ satellites distributed across 6 orbital planes at an altitude of approximately 780 km.

The network topology is dynamic due to the high mobility of LEO satellites.
1.  **Access Links**: Users upload tasks to visible satellites via uplink channels.
2.  **Inter-Satellite Links (ISL)**: Satellites communicate with neighboring satellites (intra-plane and inter-plane) to offload tasks or relay results. Connectivity is determined by Line-of-Sight (LOS) visibility and distance constraints (typically $d \le 5000$ km).
3.  **Feeder Links (SGL)**: Satellites downlink processed results to Ground Stations (GS) for cloud integration.

The system state changes dynamically based on orbital mechanics, modeled using high-fidelity rigid body dynamics (Basilisk framework).

### B. User Model

We consider a set of active users distributed geographically on Earth.
*   **User Distribution**: Users are distributed based on population density (e.g., NASA GPW dataset) or randomly within coverage zones.
*   **Access**: A user connects to satellite $s_i$ if the elevation angle $\theta_{elev}$ exceeds the minimum threshold $\theta_{min}$ (e.g., $15^\circ$).

### C. Task Model

Tasks are generated by users and arrive at the system following a Poisson process with arrival rate $\lambda$ (tasks/s). Each task $k$ is characterized by a tuple:
$$ \mathcal{T}_k = \{ D_k, \Gamma_k, T^{max}_k, loc_k \} $$
where:
*   $D_k$: Data size (in bits), assumed to be uniform or normally distributed (e.g., $8 \sim 16$ Mbits).
*   $\Gamma_k$: Computation intensity (in CPU cycles/bit), representing the complexity (e.g., $10 \sim 18$ cycles/bit).
*   $T^{max}_k$: Maximum tolerable latency (deadline), fixed at 5 seconds for delay-sensitive edge tasks.
*   $loc_k$: The origin location of the task.

Upon arrival at a source satellite $s_{src}$, the task can be:
1.  Processed locally.
2.  Offloaded to neighbor satellites via ISL.
3.  (Optional) Offloaded to ground cloud if SGL is available (not primary in this edge computing focus).

### D. Communication Model

We implement a **Dynamic Transmission Rate Model** based on the Shannon-Hartley theorem, linking data rate to transmission power and distance. This allows the RL agent to trade off energy consumption for lower transmission latency.

#### 1. Path Loss Model
For a link between node $i$ and $j$ with distance $d_{i,j}$, the free-space path loss $L_{i,j}$ is:
$$ L_{i,j} = \left( \frac{4 \pi d_{i,j} f_c}{c} \right)^2 $$
where $f_c$ is the carrier frequency (e.g., 23 GHz for Ka-band) and $c$ is the speed of light.

#### 2. Inter-Satellite Link (ISL) Rate
The dynamic transmission rate $R^{ISL}_{i,j}$ from satellite $i$ to $j$ is calculated as:
$$ R^{ISL}_{i,j}(P_{tx}, d_{i,j}) = B_{ISL} \cdot \log_2 \left( 1 + \frac{P_{tx} G_t G_r}{L_{i,j} N_0 B_{ISL}} \right) $$
where:
*   $P_{tx}$: Transmission power allocated by the agent ($P_{tx} \in [0, P_{max}]$).
*   $B_{ISL}$: Allocated ISL bandwidth (e.g., 40 MHz).
*   $G_t, G_r$: Antenna gains.
*   $N_0$: Noise power spectral density.

#### 3. Satellite-to-Ground Link (SGL) Rate
Similarly, the downlink rate to a ground station is:
$$ R^{SGL}_{i,GS}(P_{tx}) = B_{SGL} \cdot \log_2 \left( 1 + \frac{P_{tx} \cdot h_{SGL}}{N_0 B_{SGL}} \right) $$
where $h_{SGL}$ is the equivalent channel gain including atmospheric attenuation.

#### 4. Transmission Delay
The transmission delay for a data packet of size $D$ is:
$$ T_{tx} = \frac{D}{R(P_{tx}, d)} $$
The propagation delay is $T_{prop} = d/c$.

### E. Computation Model

Each satellite is equipped with an edge computing server.

#### 1. Processing Delay
The processing time for a task sub-problem of size $D_k^{sub}$ allocated to satellite $i$ is:
$$ T_{comp, i} = \frac{D_k^{sub} \cdot \Gamma_k}{f_{cpu, i}} $$
where $f_{cpu, i}$ is the CPU frequency configured by the agent, bounded by $[f_{min}, f_{max}]$ (e.g., 2.4 - 4.8 GHz).

#### 2. Energy Consumption
The power consumption of the satellite includes base platform power, transmission power, and computation power. The computation power follows a cubic relationship with frequency:
$$ P_{cpu, i} = \kappa \cdot (f_{cpu, i})^3 $$
where $\kappa$ is the effective switched capacitance coefficient.
The total energy consumption for a time slot $\tau$ is:
$$ E_{total} = \int_{0}^{\tau} (P_{base} + P_{tx}(t) + P_{cpu}(t)) dt $$

### F. Problem Formulation

The problem is formulated as a Decentralized Partially Observable Markov Decision Process (Dec-POMDP), defined by the tuple $\langle \mathcal{S}, \mathcal{A}, \mathcal{O}, \mathcal{R}, \gamma \rangle$.

#### 1. Observation Space ($\mathcal{O}$)
Each satellite agent $i$ observes its local state and partial information from neighbors:
$$ o_i(t) = \{ \mathbf{p}_i, \mathbf{v}_i, E_{bat, i}, Q_{len, i}, \mathbf{N}_{info} \} $$
*   $\mathbf{p}_i, \mathbf{v}_i$: Orbit position and velocity.
*   $E_{bat, i}$: Current battery level.
*   $Q_{len, i}$: Local task queue length.
*   $\mathbf{N}_{info}$: Relative position and status (queue, battery) of connected ISL neighbors.

#### 2. Action Space ($\mathcal{A}$)
We employ a continuous action space to enable fine-grained control. The action vector $a_i(t)$ includes:
$$ a_i(t) = \{ \alpha_{local}, \alpha_{n_1}, \dots, \alpha_{n_k}, \beta_{cpu}, \beta_{tx}, \beta_{sleep} \} $$
*   $\alpha$: Task splitting/offloading ratios ($\sum \alpha = 1$).
*   $\beta_{cpu}$: CPU frequency ratio ($f_{cpu} = \beta_{cpu} \cdot f_{max}$).
*   $\beta_{tx}$: Transmission power ratio ($P_{tx} = \beta_{tx} \cdot P_{max}^{tx}$).
*   $\beta_{sleep}$: Platform power mode (active/sleep management).

#### 3. Reward Function ($\mathcal{R}$)
The objective is to minimize latency and energy consumption while maximizing task completion rate. The global reward is a weighted sum:
$$ r(t) = w_1 \cdot N_{completed} - w_2 \cdot T_{latency} - w_3 \cdot E_{consump} - \text{penalties} $$
where $T_{latency}$ accounts for computation, transmission, and propagation delays across the entire path. Failure to complete a task within $T^{max}$ results in a large penalty.
